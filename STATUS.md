# Rift: current status

**As of 26 Oct 2026** (`main` at the commit that last changed this file). Rift (formerly Simulation-Rift) is in development: Phases 2, 3 and much of 7 of the roadmap are built and tested on Android emulators (Phases 0–7, [architecture §22](docs/architecture.md)). Architecture 3.0 (26 Oct 2026, app 0.10.0) adds **Rift AI's page model**, which reads the opened page (its forms, links, scripts, brand and wording) and warns before anything is typed: on sites it never saw it flags 54% of phishing pages at High with 0.23% false alarms ([report](docs/reports/page-model.md)); **trackers named and explained** in links (with one-tap removal) and in the live watch; **Check the live page** as the way to check a site with real data, Check itself staying offline; **refusal of a WebView missing exploited-in-the-wild fixes**; and the fixes from an internal security review ([release report](docs/reports/release-3-0.md)). Architecture 2.9 (24 Oct 2026) adds **threat lists to Check**: HaGeZi's Threat Intelligence Feeds, Phishing Army, uBlock Origin's badware list and StevenBlack's hosts, matched on the phone and kept up to date by themselves, with which Check calls 97.7% of current phishing links dangerous, up from 20% (URLCheck's hosts check: 0%; partly circular, see the report), and an optional, encrypted **history of checked links** ([report](docs/reports/release-2-9.md), [accuracy](docs/reports/check-accuracy.md)). Architecture 2.8 (24 Oct 2026) adds **Skip sign-ins and pop-ups**: one switch that takes down sign-in walls with maintained lists (Dandelion Sprout, AdGuard, Fanboy, uBlock Origin) and dismisses pages' dialog boxes; the lists and the ClearURLs rules then keep themselves up to date, and Check names a link to a listed tracker server ([report](docs/reports/release-2-8.md)). Architecture 2.5 (22 Oct 2026) adds **decoys**: a page that asks for the camera, microphone, location, files, clipboard, notifications or sensors gets something made up, and the live check lists what it asked for; and a link shared to Rift gets a **verdict sheet** over the sharing app, with the reasons and Open in Rift. Architecture 2.4 (21 Oct 2026) adds **Check**, which judges a link without opening it, and **Rift AI**, an advisory URL model that runs on the device. Architecture 2.3 (21 Oct 2026) made it smaller: **Rift keeps nothing after a session**, so the vault, its passphrases and export are gone, and the home screen was redesigned around opening a link, with a weekly summary. Android comes first; Linux is future work. It is **not** a usable or audited security product. Every claim below means "tested in the stated environment", nothing more. The full history, all findings and the per-phase evidence are in [`docs/reports/project-status.md`](docs/reports/project-status.md) and the reports next to it.

## In one paragraph

The Android debug build works end to end on emulators, and its browser is now isolated by the operating system rather than by "deleting cookies". The browser is a **separate app with its own Linux user ID**, so code that escapes the web engine cannot see Rift's files, keys or quarantine. A **network lock** gives it no route to any network except Rift's own checking proxy: a VPN that applies only to the browser and drops every packet, plus a loopback proxy that needs a per-session token and refuses local and private addresses. At every reset **Android itself wipes the browser app** (all its processes are killed and all its data deleted), and Rift checks that a fresh instance holds no file at all. While a page is open, the browser's bar shows a **live status of the session**: whether a page has loaded from an address the threat database lists, asked for your location, camera, microphone, files, clipboard or sensors (and was given decoys), probed your local network or tried to connect around the proxy (WebRTC), and what each download's scan found. It says "Danger", "Warning" or "Nothing suspicious seen so far", never "safe", and comes only from Rift's own enforcement points, not from anything the page says. Downloads are re-fetched into encrypted per-session quarantine, previewed and scanned in isolated worker processes. Nothing is kept after a session, and nothing asks for a password. The home screen, light or dark with the system, puts the link field first and shows **this week's counts**: threats blocked, dangerous files, warnings and links checked, stored as numbers per day only. The only threat database is a harmless demo one. The debug build has been installed and started on one phone (Huawei, Android 12); the test suite has not run on a phone. Hardening has started on Android. **The Linux app (Qt, Flatpak) is future work**, but it is built and passes an end-to-end test in CI: each session's browser runs in a Flatpak sub-sandbox with **no network at all** except Rift's proxy (not even the host's loopback), its renderers are sandboxed by the engine and checked before a page is shown, and files are scanned in workers that confine themselves with Landlock and seccomp. Its window, previews and the local-host exception are driven through accessibility in that test; it has not run on a desktop distribution (Wayland, a GPU).

## Updates and releases (26 Oct 2026)

Releases and updates run without a maintainer: a signed release is built from `main` each week when the app's code changed and CI has passed it (`.github/workflows/release.yml`), and installs through Obtainium; Dependabot's updates (versions at least 7 days old), the exploited-WebView list (`kev.yml`, from CISA's catalogue) and Rift AI's monthly retrain merge themselves when CI passes. The APK signing key is therefore also in GitHub's secrets ([key policy](docs/reports/key-policy.md#the-apk-signing-key)). Not yet seen end to end: no automatic release, KEV update or Dependabot merge has run at the time of writing.

## How the browser is isolated (Android)

| Boundary | What enforces it | Tested by |
|---|---|---|
| Browser cannot read Rift's data | A separate APK, so a separate Linux UID; Rift's directories return `ENOENT` from the browser's process | S23 |
| Browser cannot use Rift's private services | Not exported; the one exported interface needs a `signature` permission and checks the caller's UID and signer on every call; it offers navigation decisions and session requests only | S23, S24 |
| Other apps cannot drive the browser or the core | The same permission and checks; the proxy answers 407 without the session token | S24 |
| Pages cannot reach your LAN, router or local services | Every engine request goes to Rift's proxy (Chromium's implicit loopback bypass removed), which refuses loopback, private and link-local addresses unless you allow a host name for the session | S9, S25 |
| WebRTC and escaped code have no network route | A VPN for the browser app only that forwards nothing: TCP, UDP and DNS are dropped; WebRTC sees only the VPN's own address | S26 |
| Links do not share a session | A link from another app opens in a new session, after Android wipes the browser app, whenever the current session has loaded a page | n5 |
| Nothing survives a reset | Android's own wipe of the browser app; a fresh instance must report zero files and a new process id; checked again from outside with root in S13 | S12, S13, S27 |
| Losing the lock ends the session | If another VPN starts, the session ends and the browser is wiped; Rift never takes the VPN back without you | S28 |
| No silent downgrade | Without the lock the browser refuses to load pages; "reduced isolation" is an explicit per-session choice, labelled for the whole session | S28, S28b |
| Listed hosts are not reached, even by a page's parts | The proxy checks every connection's destination against the threat database before resolving it (HTTPS by host only); an address too long to check is refused | w1, Rust tests |
| Page content stays out of shared system state | No recents screenshot of the browser window (API 33+); every text field, in pages and in Rift, asks the keyboard not to learn | h2; H1 (the stored snapshot is a blank fill, decoded with root) |
| Other apps cannot draw over Rift, autofill it or read its screen | Both apps hide other apps' overlays (API 31+; on API 30 touches through them are dropped), keep their fields and pages away from autofill services, mark their windows for accessibility tools only (API 34+) and keep no recents snapshot | h3, H4 (each against an outsider app acting as overlay, autofill service and accessibility service, with a control of its own window) |

**Extra isolation (optional, 2.5):** with Shizuku or Sui, Rift's helper (shell or root, in its own process) has Android ignore the browser app's clipboard and clear the browser app at each reset itself; with root, a firewall lets the browser's UID reach only its proxy on loopback and the lock's VPN. Tested by z1 on API 34 (Shizuku as shell) and API 35 (Shizuku as root); the CI suites skip it, because they run no Shizuku ([architecture §8.9](docs/architecture.md)).

**Filters and tabs (2.5):** a Filters tab blocks ads and trackers and hides cookie banners, pop-ups and social sign-in prompts, using upstream lists (EasyList, uBlock Origin, Fanboy) that you download when you tap, matched by the `adblock` engine in Rift's core; each list has a switch, and you can add your own rules ([architecture §10.9](docs/architecture.md)). The home screen is five tabs (Home, Filters, Activity, Security, About) in place of one long scroll. Tested by F1 on API 34 and 35 with your own rules, and by hand with the ten real lists on API 34 (217,850 rules; a news site loaded with 12 requests blocked). Not tested: on a phone; the lists' effect on how sites look beyond that one; WebSockets and service workers are not filtered.

**Link tools (2.5):** Check and the share sheet can now clean a link (tracking parameters off, redirect links unwrapped, with the ClearURLs rules you download from the Filters tab; LGPL v3, not shipped), switch it to HTTPS or drop its query, edit it, copy, share or open it in another app after a warning, and find **where it goes**: on tap, the core follows its redirects without loading a page, checks every hop with the threat database and Rift AI before contacting it, and shows the most serious verdict along the way. Each change is checked again, with Undo. No VirusTotal and no history, unlike URLCheck. Tested by `rift-core` and `rift-ffi` unit, property and fuzz tests, and V3 on the API 34 emulator ([architecture §10.10](docs/architecture.md)). Not tested: on a phone; a trace through real shorteners (the device test cannot reach the internet-free fixture, which is on loopback and refused).

**One file, a lock switch (2.5):** Rift's APK carries the browser's and installs it on first launch through Android's own installer, after you allow Rift to install apps, so the browser stays a separate app with its own UID. The **Network lock** switch on the home screen turns the VPN off for people who need their own VPN: sessions then run with reduced isolation, labelled, and still only through Rift's proxy. Release builds are arm64 only: 23.2 MB, down from 47.8 MB. Tested by s28c on API 34 and 35 and the install by hand on API 34 ([architecture §8.8, §8.10](docs/architecture.md)).

**What it does not do:** without root, escaped browser code can still reach **loopback** (other apps' local servers on the phone), which no Android VPN covers; only one VPN can run on a device, so users of another VPN get reduced isolation or nothing; the proxy does not see inside HTTPS; and a WebView exploit still has the current session's own browsing data. These are listed in [architecture §24](docs/architecture.md).

## Main limitations

| Limitation | Workaround or way forward |
|---|---|
| The threat database that blocks is Phishing.Database only (phishing pages), signed with demo keys until the key ceremony; no malware-host list can be redistributed under its terms yet. Check's threat lists (2.9) cover malware and scam hosts too, but only warn, and are not signed by Rift: a list's server decides what Check warns about. | Written consent from abuse.ch for URLhaus, or an adapter with the user's own key. Rift AI covers resemblance, not known threats: on never-seen sites it misses about 1 in 5 phishing pages entirely. |
| One physical phone (Huawei, Android 12), and no fault rounds on a phone. | Run `android/run-tests.sh <dir>` on other phones; the fault rounds and S13/S14 need `adb root`, which retail phones do not give. |
| Escaped browser code can reach loopback services on the device. | No Android mechanism closes loopback for one app; on Linux the browser's network namespace has only its own loopback (measured in CI). |
| One VPN per device: the lock cannot run next to another VPN. | Reduced isolation for one session, chosen and labelled; never automatic. |
| If the controller is killed mid-session, the lock goes with it until the next launch wipes the browser. | The browser exits when the core dies; Android's always-on VPN with "block connections without VPN" would close the gap (a device setting). |
| An accessibility service that declares itself a tool for users with disabilities still reads Rift's windows, and below API 34 every one does; the keyboard sees what is typed. | Install only accessibility services you trust; Google Play reviews the tool declaration, sideloading does not. |
| The live page watch cannot see what scripts do inside a page (fingerprinting, keystrokes, mining) or what a page writes to the clipboard; for HTTPS only hosts are checked against the database. | Stated in the watch itself; the network lock and the wipe at reset do not depend on the watch. |
| The sites a page reaches see the phone's IP address, and so roughly where it is (city or provider). Rift hides the device's model, time zone, GPU and memory and gives made-up answers for location, camera and the rest (i1), but cannot hide the address the traffic comes from. | A VPN or Tor would hide it; Rift's network lock holds the one VPN slot, so that is not available inside Rift yet. |
| Sites that use HTTP authentication cannot be signed in to. | Only the proxy's own challenge is answered, so the token never reaches a site. |
| `blob:`, `data:` and POST downloads cannot be captured. | Stated as unsupported. |
| The Android worker is weaker than the Linux one (Android allows exec memory and `AF_UNIX`). | A seccomp filter on the parser thread; defence in depth, not a boundary. |
| The native code budget is tight: 19.2 MB (arm64) and 24.5 MB (x86_64) per ABI, against 25 MB. | The core's TLS and the update checks share one crypto library; measure every native addition. |
| Update expiry trusts the device clock; demo signing keys are one per role on one machine. | The clock is checked against the database's creation time (a fast clock cannot be detected offline); the production key policy is on the list. |
| Nothing is kept: a file you want after the session has to be downloaded again elsewhere. | By design since 2.3; files are for viewing inside Rift. |
| Wasmtime advisories, pulled in through YARA-X. | Scoped exceptions in `cargo deny`, removed once YARA-X depends on Wasmtime ≥ 48.0.6. |
| Dev machine: Docker builds the Linux workspace only one job at a time (`-j 1`, out of memory otherwise) and cannot run Flatpak; Apple silicon cannot run x86_64 emulators. | CI runs the Flatpak and the emulators. |
