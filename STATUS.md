# Rift: current status

**As of 22 Oct 2026** (`main` at the commit that last changed this file). Rift (formerly Simulation-Rift) is in development: Phases 2, 3 and much of 7 of the roadmap are built and tested on Android emulators (Phases 0–7, [architecture §22](docs/architecture.md)). Architecture 2.5 (22 Oct 2026) adds **decoys**: a page that asks for the camera, microphone, location, files, clipboard, notifications or sensors gets something made up, and the live check lists what it asked for; and a link shared to Rift gets a **verdict sheet** over the sharing app, with the reasons and Open safely. Architecture 2.4 (21 Oct 2026) adds **Check**, which judges a link without opening it, and **Rift AI**, an advisory URL model that runs on the device. Architecture 2.3 (21 Oct 2026) made it smaller: **Rift keeps nothing after a session**, so the vault, its passphrases and export are gone, and the home screen was redesigned around opening a link, with a weekly summary. Android comes first; Linux is future work. It is **not** a usable or audited security product. Every claim below means "tested in the stated environment", nothing more. The full history, all findings and the per-phase evidence are in [`docs/reports/project-status.md`](docs/reports/project-status.md) and the reports next to it.

## In one paragraph

The Android debug build works end to end on emulators, and its browser is now isolated by the operating system rather than by "deleting cookies". The browser is a **separate app with its own Linux user ID**, so code that escapes the web engine cannot see Rift's files, keys or quarantine. A **network lock** gives it no route to any network except Rift's own checking proxy: a VPN that applies only to the browser and drops every packet, plus a loopback proxy that needs a per-session token and refuses local and private addresses. At every reset **Android itself wipes the browser app** (all its processes are killed and all its data deleted), and Rift checks that a fresh instance holds no file at all. While a page is open, the browser's bar shows a **live status of the session**: whether a page has loaded from an address the threat database lists, asked for your location, camera, microphone, files, clipboard or sensors (and was given decoys), probed your local network or tried to connect around the proxy (WebRTC), and what each download's scan found. It says "Danger", "Warning" or "Nothing suspicious seen so far", never "safe", and comes only from Rift's own enforcement points, not from anything the page says. Downloads are re-fetched into encrypted per-session quarantine, previewed and scanned in isolated worker processes. Nothing is kept after a session, and nothing asks for a password. The home screen, light or dark with the system, puts the link field first and shows **this week's counts**: threats blocked, dangerous files, warnings and links checked, stored as numbers per day only. The only threat database is a harmless demo one. The debug build has been installed and started on one phone (Huawei, Android 12); the test suite has not run on a phone. Hardening has started on Android. **The Linux app (Qt, Flatpak) is future work**, but it is built and passes an end-to-end test in CI: each session's browser runs in a Flatpak sub-sandbox with **no network at all** except Rift's proxy (not even the host's loopback), its renderers are sandboxed by the engine and checked before a page is shown, and files are scanned in workers that confine themselves with Landlock and seccomp. Its window, previews and the local-host exception are driven through accessibility in that test; it has not run on a desktop distribution (Wayland, a GPU).

## Phases

| Phase | State |
|---|---|
| 0: Feasibility (14 proofs of concept) | **Mostly done.** All pass in at least one environment, including A8 (the browser split and the network lock). Open: the lookup benchmark on a phone, the Linux checks inside Flatpak, and L4 (the Linux network lock). |
| 1: Foundations (Rust core, protocol, formats) | **Done.** Unit, property and fuzz tests, strict lints, dependency policy. |
| 2: Android vertical slice | **Done on emulators** (API 33–36, both ABIs, 16 KB pages), now on architecture 2.1 (browser app and network lock, [report](docs/reports/browser-isolation.md)). Gate still open: a physical phone. |
| 3: Scanner and signed intelligence | **Done on emulators**, except real feeds and the signing-key ceremony. The release key policy is built and tested on the host: one key per holder, a 2-of-3 root, offline targets keys, and root rotation; a device starts each update from the newest root it has verified, so a rotation cannot be undone with the retired keys (finding 64, fixed; [policy](docs/reports/key-policy.md)). Scanning (two isolated workers at a time); signed updates imported from a folder you choose or fetched online through the core's own checked fetcher; refusals in one sentence; a warning when the clock is behind the database. |
| 4: Vault | **Removed in architecture 2.3.** It was built and tested on the API 35 emulator ([report](docs/reports/phase-4.md)): a Keystore key or a passphrase, keep, warned export, lock policy, recovery passphrase. Rift is for opening things once and keeping nothing, so passwords and stored files were burden and attack surface without a use. Its age sealing remains for each session's quarantine; a vault left by an earlier build is deleted at start-up, with its Keystore key. |
| 6: Rift AI | **Built (2.4), on Android** ([report](docs/reports/rift-ai.md)). A logistic-regression model of URLs (1.3 MB) trained by `tools/rift-train` on Phishing.Database, URLhaus, PhiUSIIL, Common Crawl and Tranco, with sites by the Public Suffix List. Trained on December 2025 and October 2026 phishing links, with its passes chosen on validation sites. On sites it never saw, it catches 56–59% of phishing at High and 82% at Elevated or High; it wrongly flags 0.07% of ordinary pages at High (0.03% on hosting platforms). A time-separated test (December's links only, tested on October's new sites) caught 48%, so it is retrained on fresh feeds. It does not score the 10,000 most visited sites. Advisory only: High asks before loading (v2), the live watch notes hosts it rates High, Check shows its score and reasons (v1). A whole check takes p50 19 µs, p95 64 µs on the emulator. Open: delivery in a signed pack, so it can be updated without an app update. |
| 7: Hardening and release | **Started on Android** ([report](docs/reports/phase-7.md)). Privacy checks: local work, updates and an idle session move no byte on any real network for either of Rift's apps, and nothing is scheduled (x1); browsing leaves only through the controller's proxy (x2). The dependency and licence inventory is written ([dependencies.md](docs/reports/dependencies.md)); it led to one crypto library (aws-lc-rs) instead of two. NAT64 addresses are now judged by the IPv4 address they carry, so IPv6-only networks work. Both apps carry generated third-party notices, shown under "Open-source licences" (l1). Android libraries are locked and scanned for advisories on every push (OSV). Killing the controller while it installs the database leaves it whole (F3/F4, 8 of 8 kills; until 2.3 also while it kept files into the vault, F1/F2). On a full disk downloads and installs fail with a message, a reset fails closed, Retry recovers once there is space, and the database stays whole (F5/F6); this found a misleading install message, now fixed. Cutting the emulator's power while it installs the database loses no install that had reported success (P3/P4, 4 of 4 cuts; P1/P2 covered the vault). Trusted text now escapes every Unicode format character, not a hand-made list that missed some (finding 63). The first long fuzz campaign (an hour per target) led to a proxy fix: an address padded past what can be checked against the threat database is now refused instead of being checked by its host alone (finding 65). The live page watch is built (w1); building it found that addresses had never been checked against the installed threat database, which they now are, along with every request through the proxy. Open: fault rounds on a phone's real storage, the rest of the fuzz campaign's record, an external review. |
| 5: Linux app | **Future work** (Android first). **Built; end to end in CI** ([report](docs/reports/phase-5-qt-design.md#the-app-built-21-oct-2026)). Qt (QML through cxx-qt) and Qt WebEngine in Flatpak, on the shared core. The browser host runs in a no-network sub-sandbox and reaches the web only through the controller's proxy, which also gets loopback; renderers are checked before any page is shown; downloads go to quarantine and are scanned by workers confined with Landlock, seccomp and rlimits; a signed demo database is verified and compiled by a worker at start; crashes and a killed controller leave no session behind. The window itself is driven through accessibility in the Flatpak: text and image previews and the local-host exception work (its vault went in 2.3). Database updates are imported from a folder or fetched online and installed only after a confined worker compiles them (the picker and an online fetch are not tested on Linux). Open: a desktop distribution with Wayland and a GPU, an external review. |

## How the browser is isolated (Android)

| Boundary | What enforces it | Tested by |
|---|---|---|
| Browser cannot read Rift's data | A separate APK, so a separate Linux UID; Rift's directories return `ENOENT` from the browser's process | S23 |
| Browser cannot use Rift's private services | Not exported; the one exported interface needs a `signature` permission and checks the caller's UID and signer on every call; it offers navigation decisions and session requests only | S23, S24 |
| Other apps cannot drive the browser or the core | The same permission and checks; the proxy answers 407 without the session token | S24 |
| Pages cannot reach your LAN, router or local services | Every engine request goes to Rift's proxy (Chromium's implicit loopback bypass removed), which refuses loopback, private and link-local addresses unless you allow a host name for the session | S9, S25 |
| WebRTC and escaped code have no network route | A VPN for the browser app only that forwards nothing: TCP, UDP and DNS are dropped; WebRTC sees only the VPN's own address | S26 |
| Links do not share a session | A link from another app opens in a new session, after Android wipes the browser app, whenever the current session has loaded a page | n5 |
| Nothing survives a reset | Android's own wipe of the browser app; a fresh instance must report zero files and a new process id; checked again from outside with root in S13 | S12, S13, S27 |
| Losing the lock ends the session | If another VPN starts, the session ends and the browser is wiped; Rift never takes the VPN back without you | S28 |
| No silent downgrade | Without the lock the browser refuses to load pages; "reduced isolation" is an explicit per-session choice, labelled for the whole session | S28, S28b |
| Listed hosts are not reached, even by a page's parts | The proxy checks every connection's destination against the threat database before resolving it (HTTPS by host only); an address too long to check is refused | w1, Rust tests |
| Page content stays out of shared system state | No recents screenshot of the browser window (API 33+); every text field, in pages and in Rift, asks the keyboard not to learn | h2; H1 (the stored snapshot is a blank fill, decoded with root) |
| Other apps cannot draw over Rift, autofill it or read its screen | Both apps hide other apps' overlays (API 31+; on API 30 touches through them are dropped), keep their fields and pages away from autofill services, mark their windows for accessibility tools only (API 34+) and keep no recents snapshot | h3, H4 (each against an outsider app acting as overlay, autofill service and accessibility service, with a control of its own window) |

**Extra isolation (optional, 2.5):** with Shizuku or Sui, Rift's helper (shell or root, in its own process) has Android ignore the browser app's clipboard and clear the browser app at each reset itself; with root, a firewall lets the browser's UID reach only its proxy on loopback and the lock's VPN. Tested by z1 on API 34 (Shizuku as shell) and API 35 (Shizuku as root); the CI suites skip it, because they run no Shizuku ([architecture §8.9](docs/architecture.md)).

**Filters and tabs (2.5):** a Filters tab blocks ads and trackers and hides cookie banners, pop-ups and social sign-in prompts, using upstream lists (EasyList, uBlock Origin, Fanboy) that you download when you tap, matched by the `adblock` engine in Rift's core; each list has a switch, and you can add your own rules ([architecture §10.9](docs/architecture.md)). The home screen is five tabs (Home, Filters, Activity, Security, About) in place of one long scroll. Tested by F1 on API 34 and 35 with your own rules, and by hand with the ten real lists on API 34 (217,850 rules; a news site loaded with 12 requests blocked). Not tested: on a phone; the lists' effect on how sites look beyond that one; WebSockets and service workers are not filtered.

**One file, a lock switch (2.5):** Rift's APK carries the browser's and installs it on first launch through Android's own installer, after you allow Rift to install apps, so the browser stays a separate app with its own UID. The **Network lock** switch on the home screen turns the VPN off for people who need their own VPN: sessions then run with reduced isolation, labelled, and still only through Rift's proxy. Release builds are arm64 only: 23.2 MB, down from 47.8 MB. Tested by s28c on API 34 and 35 and the install by hand on API 34 ([architecture §8.8, §8.10](docs/architecture.md)).

**What it does not do:** without root, escaped browser code can still reach **loopback** (other apps' local servers on the phone), which no Android VPN covers; only one VPN can run on a device, so users of another VPN get reduced isolation or nothing; the proxy does not see inside HTTPS; and a WebView exploit still has the current session's own browsing data. These are listed in [architecture §24](docs/architecture.md).

## What works today (Android debug build)

| Feature | What it does | Tests |
|---|---|---|
| Disposable, isolated browser | System WebView in the separate browser app, behind the network lock; no native bridges or device permissions; refuses to browse if the engine sandbox or the lock cannot be confirmed, or WebView is too old. | S1, S2, S15, S23–S28, N1–N4 |
| Navigation policy | Blocks addresses the threat database lists and automatic external-app links, asks before lookalike addresses, marks unencrypted pages, explains every decision. Every address is judged as the engine reads it (WHATWG URL), and Rift loads exactly that form. | N1–N5, w1 |
| Links from other apps | Rift can be chosen as the browser or sent a link. The link in a shared message is found (defanged ones too: `hxxps://`, `[.]`), and each link from another app opens in a new, wiped session once the current one has loaded a page. | n5 |
| Live page watch | The bar shows the session's status and a list of what its pages tried (location, camera, microphone, files, local network, connections around the proxy, listed addresses and hosts, downloads and their verdicts), with what is not watched; the home screen shows it too. Only a reset clears it. | w1 |
| Download capture | Downloads are re-fetched by the Rust core (destination checks on every redirect, size limit, cookies only to their origin) into encrypted quarantine. Hostile names are display-only. | S8–S10 |
| Previews | Images and PDFs render in an isolated worker (no files, no network, seccomp on the parser thread, deadlines, unbound after each job). Text is shown as escaped plain text. | P1, P2, S3–S7, S19 |
| Scanning | Each download is checked by file hash and type in the core, then by YARA-X rules in a fresh isolated worker, two at a time, so a hung worker does not hold the queue. A scan keeps the database snapshot it started with. The best status is "Not flagged", never "safe". | S16a, S21a, S21b |
| Signed threat database | TUF updates from a folder you choose (system picker) or online through the core's checked fetcher. Tampered, rolled-back, expired or wrongly signed updates are refused with a one-sentence reason (the full error goes to the log) and the old database stays. Debug builds embed a signed demo database. | S16, S17, S21, S22 |
| Files from other apps | Open an image, PDF or text file with Rift, or share any file to it: it is copied into the session's encrypted quarantine (same limits as a download), scanned, and opened in a full-screen viewer drawn by the isolated worker (pinch to zoom). Rift's own providers and bare `file:` paths are refused. | n6, rift-ffi intake tests |
| Check a link | **Check** judges a link without opening it: the threat database's verdict, the policy's findings and Rift AI's 0–99 score with up to three reasons ("not scored" on the 10,000 most visited sites), and how long it took. It never says "safe". | v1, rift-ffi ai tests |
| Rift AI | An advisory URL model on the device: a navigation it rates High asks before loading, and a connection to a host it rates High is noted in the live watch. Nothing is sent anywhere; it never learns from what you open. | v1, v2, w1, rift-core urlmodel tests |
| Home screen | One screen, light or dark with the system (wallpaper colours on Android 12+): the link field, **Check** and "Open safely" first, then the live check, this week's counts, the session's files with their verdicts and "View safely", and the protection details. A new logo for both apps. No passwords anywhere. | n5, h2, h3, l1, w1 |
| Weekly summary | Threats blocked, dangerous files, warnings and links checked over seven days, and a chart per day. Counted from the live watch's own events, once per session and subject; stored as numbers per day for 14 days, with no address or name. | TalliesTest (JVM), w1 run |
| Reset and recovery | Reset stops the proxy, crypto-shreds quarantine, has Android wipe the browser app and verifies the result. A kill in the middle of a reset is recovered on the next start; the browser is also wiped at every launch. | S12, S13, S14, S27 |

## Main limitations

| Limitation | Workaround or way forward |
|---|---|
| No real threat coverage in the database: only the demo database exists. | Real feeds need a licensing review; the demo label is shown on every verdict. Rift AI covers resemblance, not known threats: on never-seen sites it misses about 1 in 5 phishing pages entirely. |
| Emulators only; no physical phone. | Connect a phone with USB debugging and run `android/run-tests.sh <dir>` (S13/S14 need `adb root`). |
| Escaped browser code can reach loopback services on the device. | No Android mechanism closes loopback for one app; on Linux the browser's network namespace has only its own loopback (measured in CI). |
| One VPN per device: the lock cannot run next to another VPN. | Reduced isolation for one session, chosen and labelled; never automatic. |
| If the controller is killed mid-session, the lock goes with it until the next launch wipes the browser. | The browser exits when the core dies; Android's always-on VPN with "block connections without VPN" would close the gap (a device setting). |
| An accessibility service that declares itself a tool for users with disabilities still reads Rift's windows, and below API 34 every one does; the keyboard sees what is typed. | Install only accessibility services you trust; Google Play reviews the tool declaration, sideloading does not. |
| The live page watch cannot see what scripts do inside a page (fingerprinting, keystrokes, mining) or what a page writes to the clipboard; for HTTPS only hosts are checked against the database. | Stated in the watch itself; the network lock and the wipe at reset do not depend on the watch. |
| Sites that use HTTP authentication cannot be signed in to. | Only the proxy's own challenge is answered, so the token never reaches a site. |
| `blob:`, `data:` and POST downloads cannot be captured. | Stated as unsupported. |
| The Android worker is weaker than the Linux one (Android allows exec memory and `AF_UNIX`). | A seccomp filter on the parser thread; defence in depth, not a boundary. |
| The native code budget is tight: 19.2 MB (arm64) and 24.5 MB (x86_64) per ABI, against 25 MB. | The core's TLS and the update checks share one crypto library; measure every native addition. |
| Update expiry trusts the device clock; demo signing keys are one per role on one machine. | The clock is checked against the database's creation time (a fast clock cannot be detected offline); the production key policy is on the list. |
| Nothing is kept: a file you want after the session has to be downloaded again elsewhere. | By design since 2.3; files are for viewing inside Rift. |
| Wasmtime advisories, pulled in through YARA-X. | Scoped exceptions in `cargo deny`, removed once YARA-X depends on Wasmtime ≥ 48.0.6. |
| Dev machine: Docker builds the Linux workspace only one job at a time (`-j 1`, out of memory otherwise) and cannot run Flatpak; Apple silicon cannot run x86_64 emulators. | CI runs the Flatpak and the emulators. |

|---|---|
